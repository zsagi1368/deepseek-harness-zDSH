# dsh ACP entrypoint (`dsh acp`)

English | [中文](acp-entrypoint.zh.md)

This document is the versioned contract for external programs that drive DeepSeek Harness agents over the [Agent Client Protocol (ACP)](https://agentclientprotocol.com/). It declares which methods an ACP client can call, how stable each one is, and what counts as a breaking change. External GUI workbenches (such as BitFun's desktop workbench) integrate against this page, not against the [acp-agent demo](../../examples/acp-agent/README.md).

## The automation-only contract

`dsh acp` is an **automation-only** ACP server over JSON-RPC stdio. The ACP client is a trusted programmatic client running on the same machine — it gets the full harness capability of the composed runtime. The bridge intentionally does NOT expose:

- interactive rendering, question panels, or reasoning streams (raw chunks, tool calls, plans, and titles stay off the wire);
- `session/load` history streaming: a resumed session does not replay its past messages to the client (see [session/resume](#sessionresume));
- embedded contexts or audio prompts.

The wire carries prompt text/images, committed assistant text/images, cancellation, one-shot permission decisions, and session resumption. Everything else belongs to the harness's UI modules.

## Transport and purity

The entrypoint speaks newline-delimited JSON (NDJSON) over stdio: each line on stdout is exactly one protocol message. No logger output ever reaches stdout; diagnostics go to stderr. A client that sees any non-NDJSON byte on stdout after `initialize` should treat the connection as broken.

## Method inventory and stability

Stability levels:

- **stable** — the method and its wire behavior are committed. A breaking change requires a major version bump and is announced here.
- **experimental** — the method exists for early integration, is gated by a capability the client must opt into, and may change or disappear in a minor version.

The bridge is a single-version agent: `initialize` answers with the one protocol version the build supports.

### initialize — stable

Standard ACP initialization. The response advertises capabilities:

- `promptCapabilities.image` — `true` only when the configured provider/model route supports image prompts AND an attachment store is composed;
- `sessionCapabilities.resume` — `{}` only when a durable session-persistence backend is composed (see [session/resume](#sessionresume)).

### authenticate — stable

Accepted no-op. The bridge is a local trusted programmatic channel and requires no authentication handshake.

### session/new — stable

Creates a fresh session. The request must carry one absolute `cwd`; `additionalDirectories` and `mcpServers` are rejected with `invalidParams`. The session id is generated by the bridge; the client uses it for `prompt`, `session/cancel`, and `session/resume`.

### session/prompt — stable

Sends one prompt to one session. The bridge admits exactly one in-flight prompt per session; a concurrent second prompt is rejected with `invalidParams`. The response's `stopReason` is `end_turn` for a normally completed turn, `cancelled` when the client cancelled, and the mapped terminal reason otherwise. Committed assistant text and images stream back as `agent_message_chunk` updates in order; a failed turn rejects the prompt and never publishes its partial output.

### session/cancel — stable

Cancels the in-flight prompt (or autonomous agent work when no prompt is in flight). An idle cancel is a no-op.

### session/resume — experimental

Resumes an existing session across connections and process restarts. The client sends the stored `sessionId` (from a previous `session/new` answer); the bridge replays the session's durable JSONL log onto a fresh agent that inherits the persisted header's `cwd` and metadata, then continues serving `prompt` normally. The next prompt's model context contains the full prior conversation, but the past messages are NOT streamed back to the client (that is `session/load`, which this bridge does not implement).

Failure semantics:

- an unknown id and an unreadable (corrupt) log both reject with `invalidParams` — the bridge never half-creates a session record;
- the method is advertised only when a persistence backend is composed; without one, an out-of-contract call fails as an internal error.

This method is experimental because ACP's load/resume method family is still evolving upstream; the capability gate is the opt-in contract. A future spec change that renames or reshapes `session/resume` will be announced as a breaking change here.

### session/load — not implemented

The upstream `session/load` method streams the entire conversation history back to the client. That is presentation-level surface, outside the automation-only contract; the bridge does not advertise `loadSession` and answers `session/load` with `method_not_found`. Use `session/resume` to continue a stored conversation without wire replay.

### Permission requests (`session/request_permission`) — stable

Tool-call permission requests surface to the client as `requestPermission` with exactly two one-shot options, derived one-to-one from `@deepseek-ai/dsh-user-approval`'s policy tiers:

| policy tier | optionId | kind |
| --- | --- | --- |
| `ask` | `allow-once` | `allow_once` |
| `never` | `reject-once` | `reject_once` |

The bridge never infers a durable grant from a client response: selecting an option applies to this one request only, and `allow_always`/`reject_always` are never offered. A client that cancels the prompt turn instead of selecting an option yields the `cancelled` approval outcome; an unknown option id fails closed to `rejected`.

## Breaking-change policy

A change is breaking when it removes or renames a **stable** method, changes a stable request/response shape incompatibly, narrows a stable permission option set, or changes the transport purity guarantee. Breaking changes require a major version bump and are recorded in this document's changelog section. Experimental methods may change in any release; capability gating lets a conforming client detect the change at `initialize` instead of guessing.

- **2026-08-28**: introduced this contract; `session/resume` added as the first experimental method; permission options derived from the user-approval policy tiers.
